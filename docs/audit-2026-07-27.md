### P0-1 — Scroll horizontal cassé sur mobile : le document fait 1176 px dans un viewport de 375 px

**Gravité** : Critique
**Fichiers** : [`src/features/trust/components/trust.tsx:16`](../src/features/trust/components/trust.tsx#L16), [`src/features/projects/components/project-tags.tsx:19`](../src/features/projects/components/project-tags.tsx#L19)

#### Mesure (Chromium, 390 × 844)

```
document.scrollWidth = 1176   clientWidth = 375   →  +801 px d'overflow
```

Chaîne de conteneurs remontée depuis la marquee :

```
DIV (Marquee)                       w=1159  min-width:0     overflow-x:hidden
DIV (wrapper aria-hidden)           w=1159  min-width:auto  overflow-x:visible  ← fuite
DIV (.relative.flex.flex-col…)      w=1159  min-width:auto  overflow-x:visible  ← fuite
DIV (cellule de grille)             w=356
```

Et, indépendamment, les rangées de mesure de `ProjectTags` :

```
ul.invisible w=703  parent w=272  parentOverflow=visible
ul.invisible w=780  parent w=272  parentOverflow=visible
```

#### Deux causes distinctes

1. **Trust** — la `Marquee` a bien `overflow-hidden`, mais **elle-même** est étirée à 1159 px : ses ancêtres sont des items de grille/flex dont le `min-width` vaut `auto` par défaut, donc ils refusent de rétrécir sous la taille de leur contenu. L'`overflow-hidden` ne sert à rien puisqu'il est appliqué *sur* l'élément déjà trop large, pas sur un ancêtre contraint.
2. **ProjectTags** — la couche de mesure hors-écran est en `position:absolute` dans un parent `relative` **sans clipping**. Un élément absolu contribue à la *scrollable overflow area* de son bloc conteneur. `invisible` (= `visibility:hidden`) masque le rendu mais **ne retire pas la boîte du flux de débordement**.

#### Impact

Sur la cible n°1 d'un portfolio (mobile), la page part en biais, les sections sont décalées, le pinch-to-zoom part de travers, et 800 px de vide s'ouvrent à droite de tout le site. Visible sur la home, `/projets`, et toute page contenant des cartes projet. Dégrade aussi le CLS.

**C'est le défaut le plus dommageable du projet** : c'est la première chose qu'un recruteur ouvrant le lien depuis LinkedIn sur son téléphone verra.

#### Solution

```diff
--- a/src/features/trust/components/trust.tsx
+++ b/src/features/trust/components/trust.tsx
-        <div className="relative flex flex-col justify-center border-border border-t pt-8 md:-my-12 md:border-t-0 md:border-l md:py-12 md:pl-8">
+        <div className="relative flex min-w-0 flex-col justify-center overflow-hidden border-border border-t pt-8 md:-my-12 md:border-t-0 md:border-l md:py-12 md:pl-8">
```

```diff
--- a/src/features/projects/components/project-tags.tsx
+++ b/src/features/projects/components/project-tags.tsx
-    <div ref={wrapperRef} className="relative mt-1">
+    <div ref={wrapperRef} className="relative mt-1 overflow-hidden">
```

> `overflow-hidden` sur le wrapper est sûr : la rangée visible est déjà mono-ligne clippée, et la rangée `sr-only` n'a pas de dimension.

Garde permanente dans `globals.css` :

```css
@layer base {
  html { overflow-x: clip; }
  body { overflow-x: clip; }
}
```

…**et** un test de non-régression (voir P1-9), sinon ça reviendra.

### P0-2 — Sur `main`, aucune page n'est pré-rendue : tout le site est rendu dynamiquement à chaque requête

**Gravité** : Critique
**Fichier** : [`src/app/[locale]/(site)/layout.tsx:11`](../src/app/%5Blocale%5D/%28site%29/layout.tsx#L11)

#### Preuve — build de `main` tel quel

```
├ ƒ /[locale]                 ƒ = server-rendered on demand
├ ƒ /[locale]/graph
├ ƒ /[locale]/mentions-legales
├ ƒ /[locale]/projets
├ ƒ /[locale]/projets/[id]
```

`.next/prerender-manifest.json` → `routes: ["/_global-error","/_not-found","/icon","/robots.txt","/sitemap.xml"]`. **Zéro page.** `.next/server/app/fr/projets/` est un dossier vide.

#### Test A/B

Remplacement du seul `(site)/layout.tsx` par la version de la branche `static-export-ftp` (qui appelle `setRequestLocale`), rebuild :

```
├ ● /[locale]              → /fr, /en
├ ● /[locale]/graph        → /fr/graph, /en/graph
├ ● /[locale]/mentions-legales
├ ● /[locale]/projets
├ ● /[locale]/projets/[id] → 20 chemins pré-rendus
```

Puis le fichier a été restauré. **Une ligne fait basculer 26 routes de SSR vers SSG.**

#### Cause

`SiteLayout` est un Server Component synchrone qui appelle `useTranslations("Nav")` sans avoir appelé `setRequestLocale`. next-intl retombe alors sur les APIs dynamiques (`headers()`), ce qui désactive le rendu statique **pour tout le sous-arbre** — donc pour toutes les pages publiques, même celles qui appellent correctement `setRequestLocale`.

#### Impact

- déploiement Vercel de `main` : une invocation de fonction serverless par visite, TTFB dégradé, coût inutile, cache CDN désactivé ;
- surtout : **ceci prouve que `main` et la branche de production ont divergé silencieusement sur un point structurel**. La correction n'existe que sur la branche de déploiement. `main` — la branche sur laquelle vous développez, testez et que vous montrez sur GitHub — est cassée sur ce point. Un reviewer technique qui clone et build `main` verra 26 `ƒ` sur un portfolio statique.

#### Solution

```tsx
// src/app/[locale]/(site)/layout.tsx
import { getTranslations, setRequestLocale } from "next-intl/server";

export default async function SiteLayout({
  children,
  params,
}: {
  children: React.ReactNode;
  params: Promise<{ locale: string }>;
}) {
  const { locale } = await params;
  setRequestLocale(locale);            // ← débloque le rendu statique du sous-arbre
  const t = await getTranslations({ locale, namespace: "Nav" });
  // …inchangé
}
```

Verrouiller avec une assertion en CI :

```ts
import manifest from "../../.next/prerender-manifest.json";
it("pré-rend toutes les routes publiques", () => {
  expect(Object.keys(manifest.routes)).toEqual(
    expect.arrayContaining(["/fr", "/en", "/fr/projets", "/fr/graph"]),
  );
});
```

### P0-3 — `shadcn` (le CLI) est en `dependencies` : 17 advisories de sécurité pour 1,6 Ko de CSS

**Gravité** : Critique
**Fichiers** : [`package.json:39`](../package.json#L39), [`src/styles/globals.css:3`](../src/styles/globals.css#L3)

#### Mesures

```
pnpm audit  →  30 vulnérabilités : 3 low | 12 moderate | 15 high
répartition par dépendance racine (findings) :
  shadcn 17  ·  next 13  ·  nuqs 13  ·  @vercel/analytics 13  ·  vitest 9  ·  jsdom 7
chemin type : . > shadcn > @modelcontextprotocol/sdk > express > body-parser

node_modules/.pnpm/shadcn@4.11.0/.../dist/tailwind.css  =  1 669 octets
package.json de shadcn  =  33 dépendances runtime (@babel/core, express, ts-morph, MCP SDK…)
```

#### Explication

`shadcn` est un **outil de scaffolding en ligne de commande**. Sa seule utilité *au build* ici est la ligne `@import "shadcn/tailwind.css"` de `globals.css` — un fichier de **1,6 Ko** qui déclare les `@custom-variant` (`data-open`, `data-closed`, `data-horizontal`, `data-vertical`, `data-disabled`…) et 2 keyframes d'accordéon utilisés par vos primitives. Pour ces 1,6 Ko, vous embarquez en dépendance de **production** un serveur MCP, Express, Babel et ts-morph.

#### Impact

- 17 findings de sécurité (dont des `high`) affichés sur le dépôt public — **le premier signal que voit un recruteur qui regarde l'onglet Security de GitHub** ;
- `pnpm install --frozen-lockfile` en CI et sur Vercel installe ~50 Mo de transitives inutiles ;
- surface d'approvisionnement (supply chain) démesurée pour un site statique.

#### Solution — 15 minutes, gain maximal

```diff
--- a/src/styles/globals.css
+++ b/src/styles/globals.css
 @import "tailwindcss";
 @import "tw-animate-css";
-@import "shadcn/tailwind.css";
+@import "./shadcn-variants.css";   /* copie locale, 1,6 Ko, versionnée */
```

```diff
--- a/package.json
   "dependencies": {
-    "shadcn": "^4.11.0",
   },
   "devDependencies": {
+    "shadcn": "^4.15.0",
```

> Si vous préférez continuer à utiliser `npx shadcn@latest add`, le déplacement en `devDependencies` suffit déjà : Vercel et la CI installent les devDeps au build, et le CLI disparaît de l'arbre de production. La copie locale du fichier de 1,6 Ko est plus robuste (elle ne casse pas si upstream renomme `dist/tailwind.css`).

Documenter le choix dans `CLAUDE.md` pour qu'un futur `shadcn add` ne le réintroduise pas.

### P0-4 — `@vercel/analytics` est cassé en production (OVH)

**Gravité** : Critique
**Fichiers** : [`src/app/[locale]/layout.tsx:1`](../src/app/%5Blocale%5D/layout.tsx#L1) et [`:70`](../src/app/%5Blocale%5D/layout.tsx#L70), [`src/messages/fr.json`](../src/messages/fr.json) (`Legal.privacyAnalytics`)

#### Preuve — console Chromium, sur chaque page

```
[ERROR] Failed to load resource: 404 (Not Found) — /_vercel/insights/script.js
[ERROR] Refused to execute script from '/_vercel/insights/script.js'
        because its MIME type ('text/html') is not executable
```

`@vercel/analytics` injecte son script depuis `/_vercel/insights/script.js`, une route servie **uniquement par l'edge Vercel**. Sur un mutualisé OVH, ce chemin n'existe pas : Apache renvoie le `404.html` (donc `text/html`), le navigateur refuse de l'exécuter.

#### Impact

1. **Aucune donnée d'audience n'est collectée en production.** Vous croyez mesurer, vous ne mesurez rien.
2. Deux erreurs rouges dans la console sur chaque page. Un dev qui ouvre les DevTools de votre portfolio — c'est-à-dire précisément le public visé — voit un site qui jette des erreurs 404.
3. Une requête réseau échouée par navigation, sur le chemin critique.
4. **Problème de conformité** : `Legal.privacyAnalytics` affirme *« La mesure d'audience éventuelle est réalisée sans cookies, à partir de données agrégées et anonymisées »*. Le prudent « éventuelle » sauve la mise juridiquement, mais vous décrivez un traitement qui n'a pas lieu. Une mention légale doit décrire la réalité.
5. ~14 Ko gzip embarqués pour rien (partagés avec sonner/nuqs, voir P2-1).

#### Solution

**(a) Retirer** — recommandé si vous restez sur OVH :

```diff
--- a/src/app/[locale]/layout.tsx
-import { Analytics } from "@vercel/analytics/next";
       <body className="min-h-full flex flex-col">
         <Providers>{children}</Providers>
-        <Analytics />
       </body>
```

```bash
pnpm remove @vercel/analytics
```

Et corriger `privacyAnalytics` en fr/en : *« Ce site n'utilise aucun outil de mesure d'audience. »*

**(b) Remplacer** par une solution compatible hébergement statique et sans cookie — Plausible/Umami self-host, ou Cloudflare Web Analytics. La mention légale devient exacte et vous récupérez de vraies données.

Si vous conservez le déploiement Vercel de `main` en parallèle (voir P2-10) :

```tsx
{process.env.NEXT_PUBLIC_VERCEL_ENV && <Analytics />}
```

### P1-1 — Soft 404 : toute URL inconnue renvoie HTTP 200 sur `main`

**Gravité** : Majeur
**Fichiers** : [`src/app/[locale]/[...rest]/page.tsx`](../src/app/%5Blocale%5D/%5B...rest%5D/page.tsx), [`src/app/[locale]/not-found.tsx`](../src/app/%5Blocale%5D/not-found.tsx)

#### Preuve — build propre de `main`, `pnpm start`

```
/fr/projets/does-not-exist   →  200      ← devrait être 404
/fr/nimportequoi             →  200      ← devrait être 404
/en/foo                      →  200      ← devrait être 404
/nimportequoi                →  307      (redirection de locale, correct)
```

En-têtes du premier cas : `x-nextjs-cache: HIT`, `x-nextjs-prerender: 1` — Next met en cache le rendu de `notFound()` et le sert avec un 200.

#### Impact

Google indexe des URL inexistantes comme des pages valides. Sur un site à 22 URL réelles, du contenu « 404 — Page introuvable » dupliqué à l'infini dans l'index dilue le peu d'autorité que vous avez. Search Console signale des « soft 404 ». C'est aussi faux pour tout crawler, monitoring ou détecteur de liens cassés.

#### Nuance importante

**En production (OVH) le problème n'existe pas.** Le `.htaccess` déclare `ErrorDocument 404 /404.html` et le catch-all `[...rest]` est supprimé sur la branche de déploiement — Apache renvoie donc un vrai 404. Le défaut est **spécifique à `main`**, ce qui en fait un symptôme de plus de la divergence P1-2, et un problème réel pour le déploiement Vercel actif sur `main`.

#### Solution

Supprimer `src/app/[locale]/[...rest]/page.tsx` sur `main` aussi (Next gère nativement les segments non appariés et renvoie 404), et vérifier le code de statut :

```ts
test("une URL inconnue renvoie un 404 HTTP", async ({ page }) => {
  const res = await page.goto("/fr/nimportequoi");
  expect(res?.status()).toBe(404);            // ← aujourd'hui : 200
  await expect(page.getByRole("heading", { name: /404/ })).toBeVisible();
});
```

> Le test actuel `projects.spec.ts` ne vérifie que le titre affiché — c'est exactement pour cela que le bug est passé.

### P1-2 — Divergence de configuration entre `main` et `static-export-ftp`

**Gravité** : Majeur
**Fichiers** : `next.config.ts`, `src/proxy.ts`, `src/app/[locale]/[...rest]/page.tsx`, `src/app/[locale]/(site)/layout.tsx`, `src/app/{sitemap,robots,icon,[locale]/opengraph-image}`

#### État mesuré

```
main → static-export-ftp : 12 fichiers modifiés, +240 / −50
commits sur main absents de static-export-ftp : 0   (aujourd'hui synchronisé)
mécanisme de synchro : merges manuels `Merge branch 'main' into static-export-ftp`
```

Le README documente ce montage et l'assume — ce n'est donc pas une erreur non identifiée. **Mais l'approche est structurellement fragile** et a déjà produit deux bugs réels :

| Divergence | Conséquence sur `main` |
| --- | --- |
| `setRequestLocale` dans `(site)/layout.tsx` | **P0-2** — 26 routes en SSR au lieu de SSG |
| `[...rest]` supprimé + `ErrorDocument 404` | **P1-1** — soft 404 en 200 |
| `dynamic = "force-static"` sur 4 routes | Divergence de comportement OG/sitemap/robots |
| `output` / `trailingSlash` / `images.unoptimized` | `main` teste des images optimisées, la prod n'en a pas |

#### Impact

Chaque merge `main → static-export-ftp` est un point de rupture manuel. Vos tests E2E, votre CI et vos builds locaux valident un artefact **qui n'est pas celui déployé** : URLs sans slash final vs avec, images avec srcset vs sans, 404 en 200 vs vrai 404, headers Next vs headers Apache. Toute la chaîne de qualité mesure la mauvaise chose.

#### Solution — supprimer la branche, piloter par variable d'environnement

```ts
// next.config.ts
const isStaticExport = process.env.BUILD_TARGET === "static";

const nextConfig: NextConfig = {
  reactCompiler: true,
  ...(isStaticExport
    ? { output: "export" as const, trailingSlash: true, images: { unoptimized: true } }
    : { headers: async () => [{ source: "/(.*)", headers: securityHeaders }] }),
};
```

```ts
// src/app/sitemap.ts, robots.ts, icon.tsx, [locale]/opengraph-image.tsx
export const dynamic = "force-static";   // inoffensif hors export, requis en export
```

- `src/proxy.ts` : le garder ; Next l'ignore avec `output: "export"`.
- Supprimer `[...rest]` des deux côtés (voir P1-1).
- Ajouter un job CI `build:static` qui lance `BUILD_TARGET=static pnpm build` et **teste `out/`** — le seul moyen de valider l'artefact réellement déployé.

Gain : une seule branche, une seule vérité, la CI teste enfin la production.

### P1-3 — Poids client : 1 156 Ko de JS non compressé (334 Ko gzip / 286 Ko brotli) sur la home

**Gravité** : Majeur
**Fichiers** : [`package.json`](../package.json), [`src/components/controls/locale-switcher.tsx`](../src/components/controls/locale-switcher.tsx), [`src/components/layout/header/mobile-nav.tsx`](../src/components/layout/header/mobile-nav.tsx), [`src/providers/index.tsx`](../src/providers/index.tsx)

| Chunk | Brut | gzip | Contenu identifié |
| --- | ---: | ---: | --- |
| `42sp58z1a78of` | 375 Ko | **95 Ko** | Radix (37 occurrences), `aria-hidden`, floating/scroll-lock |
| `2m1jtrqwl-z9c` | 222 Ko | 69 Ko | react-dom |
| `0v73yek2isiab` | 135 Ko | 36 Ko | react / Scheduler |
| `0cz1d0mv5g_q7` | 110 Ko | 38 Ko | runtime Next |
| `12z-655cd8b6x` | 49 Ko | **14 Ko** | **sonner (126 réf.) + nuqs (29) + @vercel/analytics** |
| `418myrx4oeim6` | 39 Ko | 11 Ko | IntlMessageFormat (next-intl) |
| … 10 autres | | | |
| **Total home** | **1 156 Ko** | **334 Ko** | |
| **Total `/graph`** | **1 347 Ko** | ~380 Ko | + React Flow/d3 (195 Ko brut) |
| HTML `/fr` | 157 Ko | 22 Ko | dont 84 Ko de payload RSC |
| CSS | 103 Ko | 17 Ko | 2 fichiers |

Référence : un site de contenu Next.js bien optimisé se situe autour de **90–130 Ko gzip**. Vous êtes à **2,5–3,5×**.

#### Trois postes évitables

**(a) Radix — 95 Ko gzip pour un menu de langue à 2 entrées et un tiroir mobile.**

`LocaleSwitcher` = `DropdownMenu` (Portal + floating-ui + DismissableLayer + FocusScope + RovingFocus + `react-remove-scroll` + `aria-hidden`). `MobileNav` = `Dialog` (même pile). Ces deux composants sont dans le `Header`, donc **sur toutes les pages**, chargés au premier octet.

Solution — le sélecteur à 2 locales n'a pas besoin d'un menu ARIA complet. Deux liens suffisent, et ils sont meilleurs pour le SEO (crawlables) :

```tsx
// composant serveur, zéro JS
export function LocaleSwitcher({ locale, path }: { locale: Locale; path: string }) {
  return (
    <div className="flex items-center gap-1" role="group" aria-label={t("switchLanguage")}>
      {routing.locales.map((l) => (
        <Link key={l} href={path} locale={l} hrefLang={l}
              aria-current={l === locale ? "true" : undefined}
              className={cn("rounded px-2 py-1 text-sm", l === locale && "bg-muted font-medium")}>
          {l.toUpperCase()}
        </Link>
      ))}
    </div>
  );
}
```

Bonus : corrige P3-5 (la langue active n'est aujourd'hui pas visible). Pour `MobileNav`, `<dialog>` natif ou l'API Popover couvrent le besoin.
**Gain estimé : 60–90 Ko gzip sur toutes les pages.**

**(b) sonner + nuqs + @vercel/analytics = 14 Ko gzip pour 3 fonctionnalités inexistantes.**

`grep` sur tout `src/` hors `shadcn-ui/` : **aucun appel à `toast()`, aucun `useQueryState`, aucun store Zustand**. Seules subsistent les déclarations dans `providers/index.tsx`. Le `<Toaster />` injecte même un landmark parasite dans l'arbre d'accessibilité (`SECTION[label="Notifications alt+T"]`) sur chaque page. Voir P2-1.

**(c) `country-flag-icons` : 9 Mo installés pour 2 drapeaux.**

Le tree-shaking limite l'impact bundle, mais c'est une dépendance entière pour deux `<svg>` de 20 lignes. Disparaît naturellement avec la solution (a).

**Objectif réaliste après (a)+(b) : ~200–240 Ko gzip sur la home**, soit −30 à −40 %.

### P1-4 — `.htaccess` n'active aucune compression : OVH peut servir le site en clair

**Gravité** : Majeur
**Fichier** : `public/.htaccess` (branche `static-export-ftp`)

Le fichier configure soigneusement `DirectoryIndex`, les redirections www→apex, `ErrorDocument`, le `ForceType` des images générées, les 5 headers de sécurité et un `Cache-Control` immutable. **Il ne contient ni `mod_deflate` ni `mod_brotli`.**

#### Impact

Si le vhost OVH n'active pas la compression par défaut pour `application/javascript` (ce qui varie selon les offres mutualisées et les versions Apache/nginx front), vos visiteurs téléchargent **1 156 Ko au lieu de 334 Ko** sur la home. Sur une 4G médiocre, c'est plusieurs secondes de LCP/TTI. Comme rien ne le vérifie, vous ne le sauriez pas.

#### Solution

```apache
# --- Compression ---------------------------------------------------------
<IfModule mod_brotli.c>
  AddOutputFilterByType BROTLI_COMPRESS text/html text/css text/plain text/xml \
    application/javascript application/json application/xml image/svg+xml
</IfModule>
<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/html text/css text/plain text/xml \
    application/javascript application/json application/xml image/svg+xml
  # Ne pas recompresser les binaires déjà compressés
  SetEnvIfNoCase Request_URI \.(?:gif|jpe?g|png|webp|avif|woff2?|pdf)$ no-gzip dont-vary
</IfModule>
```

Puis **vérifier** une fois en ligne :

```bash
curl -sI -H 'Accept-Encoding: br, gzip' https://algont-ier.com/_next/static/chunks/<hash>.js \
  | grep -i content-encoding
```

Corollaire : le `Cache-Control: immutable` s'applique via `<FilesMatch "\.(js|css|…)$">` à **tous** les JS/CSS. Restreindre au dossier hashé serait plus sûr :

```apache
<Directory "/_next/static">
  Header set Cache-Control "public, max-age=31536000, immutable"
</Directory>
```

### P2-10 — Double déploiement : Vercel sur `main` **et** OVH en production, sans canonicalisation croisée

**Gravité** : Moyen
**Fichiers** : [`vercel.json`](../vercel.json), [`package.json`](../package.json) (`vercel-build`)

```json
"git": { "deploymentEnabled": { "main": true, "master": true } }
```

Chaque push sur `main` produit un déploiement Vercel public sur `*.vercel.app`, alors que la production est sur OVH. Les deux servent **le même contenu**, mais :

- les canoniques du build Vercel pointent vers `NEXT_PUBLIC_SITE_URL` — si la variable n'est pas définie côté Vercel, elle retombe sur `http://localhost:3000` (le `.default()` de `src/env.ts`), et vous publiez des canoniques cassées ;
- si elle vaut le vrai domaine, l'aperçu Vercel se déclare canonique de `algont-ier.com`, mais son `robots.txt` autorise `allow: "/"` ;
- soft 404 en 200 (P1-1) et rendu 100 % dynamique (P0-2) sont *actifs* sur cette copie.

**Impact** : risque de contenu dupliqué indexé, et un second site public dont personne ne surveille l'état.

#### Solution

- **(a)** Désactiver les déploiements de production Vercel (`"deploymentEnabled": { "main": false }`), ne garder que les previews de PR, et forcer `X-Robots-Tag: noindex` dessus.
- **(b)** Basculer la production sur Vercel et supprimer OVH — vous récupérez l'optimisation d'images, les vrais 404, l'ISR, Analytics fonctionnel. Mais ce n'est pas la contrainte fixée, donc plutôt (a).

Dans tous les cas : **retirer le `.default("http://localhost:3000")` en production**. Un défaut silencieux sur une variable qui pilote canoniques et sitemap est un piège :

```ts
NEXT_PUBLIC_SITE_URL: process.env.NODE_ENV === "production"
  ? z.url()                                    // obligatoire, le build casse si absente
  : z.url().default("http://localhost:3000"),
```

Note connexe : `SKIP_ENV_VALIDATION: "true"` est actif dans **les deux jobs CI**, y compris pour l'étape `build`. Le commentaire du workflow le dit lui-même. Vous construisez donc en CI sans jamais valider l'environnement — la protection que `src/env.ts` est censé apporter n'est active nulle part.

### P2-14 — `useMemo` dans `skills-graph` contredit une règle explicite de `CLAUDE.md`

**Gravité** : Moyen
**Fichiers** : [`src/features/graph/components/skills-graph.tsx:189`](../src/features/graph/components/skills-graph.tsx#L189), [`CLAUDE.md`](../CLAUDE.md)

> `CLAUDE.md` : *« **React Compiler** is enabled — no manual `useMemo`/`useCallback`/`memo`. »*
> `skills-graph.tsx:189` : `const layout = useMemo(buildLayout, []);`

**L'intention est légitime** : `buildLayout()` lance une simulation d3-force de **400 ticks** sur ~52 nœuds, synchronement pendant le rendu. Ce n'est pas une mémoïsation d'optimisation, c'est une garantie d'exécution unique — et le React Compiler ne *garantit* pas ça (il optimise, il ne contractualise pas).

Mais le code exprime mal l'intention : `useMemo` **signale** « optimisation », alors qu'il s'agit d'une initialisation. La primitive correcte est l'état paresseux :

```diff
-  const layout = useMemo(buildLayout, []);
+  // Initialisation paresseuse : la simulation d3 (400 ticks) ne doit tourner
+  // qu'une fois. useState(initializer) le garantit, contrairement à useMemo.
+  const [layout] = useState(buildLayout);
```

**Point plus profond** : cette simulation bloque le thread principal au montage. Sur 52 nœuds c'est acceptable, mais elle grandit en O(n²) avec `forceManyBody`. À 30 projets ce sera perceptible. Voir R-4.

Un Staff engineer lit ça comme : aucun filtre, aucune hiérarchie, aucune conscience de ce que « maîtriser » signifie. **Vingt-cinq compétences réelles impressionnent plus que soixante déclarées** — la première liste dit « je sais choisir », la seconde dit « j'ai peur d'oublier quelque chose ».

**5. Sept tests unitaires, dont quatre sur `twMerge(clsx())`.** *(P1-9)*
Testing Library installée, configurée, jamais utilisée. Le seul code non trivial du dépôt n'est pas testé. Chez Stripe ou Shopify, l'absence de tests n'est pas un manque de temps : c'est un signal sur la façon dont vous concevez la fiabilité.

**6. `git status` affiche 40 fichiers en attente.** *(P3-12)*

**7. Une branche de déploiement qui fait fork de la production.** *(P1-2)*
Un lead reconnaît immédiatement le motif — et sait où ça finit. La preuve est déjà là : `main` est en SSR total et renvoie des 200 sur les 404 parce que les correctifs ne vivent que sur l'autre branche.

## Refactorings majeurs

### R-1 — Unifier `main` et `static-export-ftp` *(3–4 h, priorité maximale)*

Config pilotée par `BUILD_TARGET`, `force-static` inconditionnel sur les 4 routes de métadonnées, suppression de la branche, job CI validant `out/`. **Résout ou prévient P0-2, P1-1, P1-2, P2-10.** C'est le refactoring dont dépendent tous les autres : tant qu'il n'est pas fait, chaque correction doit être portée deux fois.

### R-2 — Sortir Radix de la couche globale *(4–6 h)*

`LocaleSwitcher` → 2 liens serveur ; `MobileNav` → `<dialog>` natif ou Popover API ; supprimer `country-flag-icons`. **−60 à 90 Ko gzip sur toutes les pages**, plus un sélecteur de langue crawlable et un état actif visible. Meilleur ratio gain/risque en performance.

### R-3 — Constituer une vraie stratégie de test *(6–8 h)*

Projet Playwright mobile, gardes d'overflow, axe-core, assertions console + code HTTP, tests de composant sur `useOneLineFit`/`ProjectTags`/`MainNav`, test de parité i18n, assertion sur `prerender-manifest`, seuil de couverture. **Transforme le point le plus faible du dossier en argument.**

### R-4 — Pré-calculer le graphe au build *(3 h)*

Les projets sont statiques : la simulation d3 n'a aucune raison de tourner dans le navigateur.

```js
// scripts/build-graph.mjs — exécuté par "prebuild"
import { projects } from "../src/features/projects/data.ts";
// … même buildLayout(), écrit dans src/features/graph/layout.generated.json
```

`SkillsGraph` importe le JSON. Résultat : **d3-force disparaît du bundle** (−195 Ko brut sur `/graph`), plus de blocage du thread principal au montage, layout déterministe (donc testable en visuel), et `useMemo`/`useState(buildLayout)` deviennent sans objet. Belle réponse à « parlez-moi d'une optimisation que vous avez faite ».

### R-5 — Consolider le contenu derrière un schéma *(4–6 h)*

`schema.ts` Zod par feature, validation au build, `types.ts` inférés, `data.ts` validé. Prépare réellement l'admin annoncé par `CLAUDE.md` et `features/README.md`. Ajouter au passage un champ `role`/`context` (« projet d'équipe HETIC », « alternance Plume SAS ») — information que les recruteurs cherchent en premier et qui n'est aujourd'hui que noyée dans les descriptions.

### R-6 — Pipeline d'images statiques *(2–3 h)*

Script `sharp` générant 400/800/1280 en WebP + AVIF, `loaderFile` custom pour conserver `next/image` en mode export, nouveau portrait 4:5. **Résout P1-8 et P1-10** et supprime `unoptimized` du vocabulaire du projet.
