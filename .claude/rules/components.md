# Where a component lives

| Folder | Content | Knows the domain? |
| --- | --- | --- |
| `components/shadcn-ui/` | shadcn primitives, generated by the CLI | no |
| `components/magic-ui/` | Magic UI registry components (e.g. marquee) | no |
| `components/layout/` | global chrome — `header/`, `footer/` | no |
| `components/controls/` | reusable controls (theme-toggle, locale-switcher) | no |
| `components/shared/` | composites used in ≥ 2 places (section, social-icons…) | no |
| `features/<name>/components/` | UI tied to one domain (hero, projects, graph…) | yes |

- Start colocated (route `_components/` or the owning feature); promote to `shared/` only at the
  **second real caller**. Features are imported through their `index.ts` (the hook refuses deep
  paths from outside).
- Server Component by default; `"use client"` only on the interactive island.
- Use `cn()` from `@/lib/utils/cn` for conditional classes.

## shadcn

- New components land in `@/components/shadcn-ui`, `cn` in `@/lib/utils/cn` (`components.json`).
  Don't hand-tweak those import paths.
- The `shadcn` package is a **devDependency** — as a dependency it drags 33 runtime packages
  (express, babel, MCP SDK) and their advisories into production. `globals.css` imports the
  vendored `src/styles/shadcn-variants.css`, never `shadcn/tailwind.css`; if `shadcn add` needs a
  new `@custom-variant`, copy it into that file. `knip.json` ignores the package (CLI, not a lib).
- After every `shadcn add`, read `git diff package.json` before going further.
